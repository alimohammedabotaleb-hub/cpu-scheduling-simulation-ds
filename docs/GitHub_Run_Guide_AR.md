# تشغيل المشروع داخل GitHub

المشروع يعمل بلغة C++17 وبالعينة المدمجة دون إدخال بيانات. يمكن تنفيذ الكود على خوادم GitHub ومشاهدة نتائجه من المتصفح باستخدام الطريقتين الآتيتين.

## العرض المباشر من المتصفح باستخدام Codespaces

1. افتح [بيئة تشغيل المشروع](https://codespaces.new/alimohammedabotaleb-hub/cpu-scheduling-simulation-ds?quickstart=1) وسجل الدخول إلى حساب GitHub.
2. أنشئ Codespace من فرع `main`، أو افتح البيئة الموجودة إذا سبق إنشاؤها.
3. انتظر حتى يكتمل تجهيز المترجم وفتح محرر الكود. يُجمع البرنامج ويُشغل مرة عند إنشاء البيئة.
4. افتح `src/CPU_Scheduling_Simulator.cpp` لعرض الكود.
5. لإعادة التشغيل أمام الدكتور، اختر `Terminal` ثم `New Terminal` ونفذ:

```bash
bash run_github.sh
```

ويمكن داخل المحرر الضغط على `Ctrl+Shift+B` لتشغيل المهمة `Run CPU Scheduling Simulator`.

تظهر العينة ونتائج FCFS وSJF وPriority وRound Robin ثم جدول المقارنة. يحفظ ناتج التنفيذ الجديد في `output/Live_Output.txt`، ويمكن فتحه وتكبير الخط أو البحث داخله عن `PERFORMANCE COMPARISON`.

لا يلزم تثبيت Dev-C++ أو g++ على الجهاز المحلي لهذه الطريقة. عند تعديل العينة داخل `main`، احفظ الملف ثم أعد تشغيل الأمر السابق ليجمع المصدر المعدل.

إنشاء Codespace يحتاج تسجيل الدخول وتوفر الخدمة والحصة في الحساب. بعد الانتهاء أوقف البيئة من قائمة Codespaces. زر فتح البيئة يعرض صفحة GitHub الخاصة بالإنشاء؛ لا ينشئ الدليل بيئة باسم الحساب تلقائيًا.

## التنفيذ الآلي داخل GitHub Actions

1. افتح [صفحة التشغيل الآلي](https://github.com/alimohammedabotaleb-hub/cpu-scheduling-simulation-ds/actions/workflows/run-project.yml).
2. اختر أحدث تشغيل مكتمل بعلامة خضراء.
3. افتح مهمة Linux أو Windows لعرض تفاصيل التجميع والتنفيذ. تعرض صفحة الملخص النتائج الفعلية أيضًا.
4. لتنزيل الملف التنفيذي والنتائج، استخدم `Artifacts` أسفل صفحة التشغيل، ثم اختر `CPU-Scheduling-Linux` أو `CPU-Scheduling-Windows`.
5. لتشغيله مجددًا، اختر `Run workflow` ثم فرع `main` ثم أكد التشغيل. يظهر هذا الخيار للحساب الذي لديه صلاحية مناسبة على المستودع.

يشغل GitHub Actions المصدر الأصلي بعد تجميعه بمعيار C++17 على Linux وWindows. يقارن الناتج بملف العينة المرجعي، وتفشل عملية التحقق إذا اختلف. عند تغيير العينة عمدًا، يجب مراجعة نتائجها وتحديث المرجع أيضًا. تظل الملفات التنفيذية والنتائج قابلة للتنزيل لمدة 30 يومًا من تشغيلها، ويمكن إنشاء نسخة جديدة بإعادة التشغيل.

## ترتيب العرض أمام الدكتور

1. اعرض بيانات العمليات داخل `main`.
2. شغل الأمر في Codespaces ليشاهد الدكتور التنفيذ الحقيقي.
3. اشرح FCFS ثم فرق الاختيار في SJF وPriority، ثم الشريحة الزمنية في Round Robin.
4. افتح جدول المقارنة: أقل متوسط انتظار في العينة الأصلية هو 5.00 في SJF، واستغلال المعالج 91.67% للجميع.
5. افتح دالة `calculateFinalStatistics` ومواضع هياكل البيانات عند السؤال عنها.

تعرض صفحة ملفات GitHub المصدر والمستندات. أما تنفيذ البرنامج فعليًا فيتم داخل Codespaces أو GitHub Actions. ويمكن قراءة التقرير الرسمي وملفات PDF مباشرة من مجلد `docs`.
